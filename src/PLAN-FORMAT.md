# PLAN-FORMAT.md

`PLAN.md` в корне проекта описывает один **план** — сущность предметной области,
с которой работает конечный пользователь. Цель — зафиксировать понимание задачи
(полностью и правильно), затем проецировать его в код; после полного покрытия
план **закрывается** (файл удаляют).

Язык — пользователя, не программиста: только наблюдаемое поведение и смысл,
никакого код-жаргона (сигнатуры, `dt`, формулы, форматы данных, «нормализация»,
«тик»). Как это считать — забота кода и тестов уровня.

Нефункциональные и кросс-сущностные требования («отклик не дольше секунды»,
«работает офлайн») — не сюда: им место в `Non-Obvious Rules` или `Verification`
уровня.

План может крениться в две стороны (формат один, разделы берёшь по надобности):
- **сущность** — главное это набор поведений (Сердечко, Портал);
- **процесс** — главное это переходы между состояниями (Заявка, Заказ). Поток во
  времени — это владелец потока со state-машиной, а не отдельная форма.

## Шаблон

```
# {Имя}

{Одна строка: что это глазами пользователя. Если **зачем** неочевидно — добавь
строку «Назначение». Иначе не добавляй.}

## Состояния
{Если есть состояния — перечисли их и что их различает. Для процесса это основа:
новая → отправлена → подтверждена → ... Каждый переход — проверяемый сценарий,
наравне с пунктами «Поведения».}

## Поведение
Пункты — это **сценарии**, то, что проверяется тестами.
- {что наблюдает пользователь, когда происходит то-то}
- ...

## Связи
С какими сущностями связан, кто кого меняет.

## Вне рамок
{Что сознательно НЕ входит сюда — отдельными планами.}
```

Заголовки шаблона канонические: агенты и проверки ищут именно их, не переводи
и не переименовывай.

## Чьё поведение

Взаимодействие двух сущностей принадлежит **активной** (инициирующей): Портал
перемещает, Сердечко лечит. Пассивная держит только свои инварианты (Персонаж:
«здоровье ≤ макс»). Если правило симметрично и ничьё — заводи отдельный
план-правило.

## Связь с кодом

Связь одна — **имя теста**: оно повторяет формулировку пункта поведения, который
покрывает; уточнения (краевые случаи) — после формулировки. Соответствие
«пункт ↔ тест» держится этим и после закрытия плана. Это и есть спека сделанного.

Ссылок на план в коде нет — не заводи. План один на ветку, значит его тесты —
это диф ветки относительно главной; ссылка ничего не различала бы, зато после
закрытия рисковала бы остаться в главной ветке указателем на удалённый файл.

Имя плана держит **ветка** (kebab-case): файл всегда `PLAN.md`, а имя одно на
всё — ветка, заголовок `# {Имя}` внутри файла, заголовок PR. Переименовал
план — тем же дифом переименуй ветку. Путь фиксирован: папки для планов нет и
вложенности нет.
