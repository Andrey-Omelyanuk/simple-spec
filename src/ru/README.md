# Simple Spec

Набор команд для ИИ-агента (opencode, Claude Code, Cursor). Понимание задачи
фиксируют **историей**, историю реализуют **кодом**, а спека сделанного живёт в
именах тестов. Цикл из двух команд: `/story` → `/do`.

## Модель

[story] → [code]

- **Story** — файл в `stories/`: голос пользователя (что нужно и зачем) и его
  дистилляция (пункты поведения). Это **append-only лог намерений**, как
  changelog: старые записи не переписывают под новый код. Story, а не **spec**:
  запись не утверждает чёткого требования — намерение пользователя может быть
  неточным и неверным, истина — в коде и тестах, а не в записи.
- **Code** — реализация и источник истины. Имена тестов на языке пользователя
  повторяют пункты поведения истории — это и есть спека сделанного.

Стрелка `→` — проекция: пункты поведения истории становятся именами тестов. Она
переживает устаревание записи: лог остаётся записью прошлого намерения, имена
тестов продолжают говорить, что сделано.

Вторая опора модели — **уровень**: `AGENTS.md` в каждой значимой папке
иерархии. Запись говорит, *что* должен увидеть пользователь; уровень говорит,
*как это проверяется* (раздел `Verification`) и какие правила нельзя вывести из
кода (`Non-Obvious Rules`). Без уровня нельзя понять, реализована ли фича.

## Цикл истории

```
main ──●──────────────────────────────────●── мерж: решение пользователя
        \                                  /
         ●── история ──●── код + тесты ──●
       /story         /do
```

`/story` — обсудить с пользователем, что нужно и зачем, и записать итог
обсуждения в `stories/` одним файлом. `/do <имя-истории>` — реализация: код и
тесты по пунктам поведения истории; `<имя-истории>` — файл из `stories/`.
Детали потоков — в командах `story.md` и `do.md`.

Мелочь ведут мимо цикла — на опечатку историю не заводят.

`/architect` — вне цикла: скелет приложения, то есть файловая иерархия с
`AGENTS.md` на каждом уровне (или готовый шаблон из `src/templates/`).

## Почему так

Постоянная спека, которую держат рядом с кодом вечно, рано или поздно перестают
обновлять — и тогда врут оба, а верить приходится коду. Simple Spec не даёт
такой спеке появиться — и не выбрасывает намерение. Намерение и понимание
задачи — в истории (`stories/`); решения, которые нельзя вывести из кода, — в
«почему»-комментариях (самое ценное — отвергнутая альтернатива) и в
`Non-Obvious Rules` уровня; отмена прежнего поведения — в сообщении коммита,
удалившего тест.

Чем это не является: не трекер задач, не обвязка над GitHub (цикл знает только
git: PR и ревью — правила проекта), не документация архитектуры (её место —
`AGENTS.md` уровня), не BDD-фреймворк — какими видами тестов проверять, решает
уровень.

## Что где лежит

- `src/commands/story.md` — история: команда и формат записи в `stories/`.
- `src/commands/do.md` — команда реализации истории.
- `src/commands/architect.md` — команда построения скелета.
- `src/LEVEL.md` — формат уровня (`AGENTS.md` в проекте): границы, паттерны,
  `Verification`.
- `src/templates/` — готовые скелеты архитектур для `/architect`
  (например `web-app/`).

## Установка

Команды и кит (`LEVEL.md`) ставит `install.sh` — в проект или глобально для
пользователя:

```
./install.sh <путь-к-проекту> [служебная-папка] [-l язык]   # по умолчанию en
./install.sh --global [opencode|claude|cursor] [-l язык]     # глобально для юзера
```

Язык текстов — флаг `-l` (по умолчанию `en`; русский — `-l ru`), его запоминает
манифест `.installed`: повторный запуск без флага держит установленный язык.
Кит едет рядом с командами, ссылки внутри команд переписываются на его путь.
Повторный запуск обновляет кит, убирает команды, которых в методе больше нет, и
не трогает `stories/` проекта. Подробности — в шапке `install.sh`.
