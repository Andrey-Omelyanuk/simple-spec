# /object-check

Режим **проверки**: насколько объект реализован в коде. Команда ничего не пишет
и не чинит — она только смотрит и докладывает. Это «измерительный прибор» для
Проекции (см. README): объект ↔ тесты ↔ код.

## Что ты делаешь

1. Находишь объект в `oos/` по имени (или берёшь все, если имя не указано).
2. Вынимаешь из файла его **поведение** (блок `## Поведение`, при наличии —
   состояния) и смысл.
3. Находишь все тесты со ссылкой на этот объект: `// object: <unique-name>`.
4. **Смыслово сопоставляешь** содержимое найденных тестов с поведением: читаешь,
   что именно тест проверяет, и решаешь, какой пункт поведения он покрывает.
   Ссылка — это только указатель на нужные тесты; покрытие определяется по сути
   теста, а не по наличию ссылки.
5. Прогоняешь эти тесты и смотришь результат.
6. Выдаёшь отчёт: что покрыто, что нет, что падает.

## Чего ты НЕ делаешь

- Не пишешь и не правишь тесты и код. Совсем. Это задача `/object`.
- Не редактируешь объект. Это задача `/object`.
- Не «чинишь» падающие тесты — только сообщаешь о них как о багах.

## Как читать результат

Для каждого пункта поведения — один из статусов:

- **✓ покрыт** — есть тест, проверяющий этот пункт, и он проходит.
- **⚠ баг** — тест на пункт есть, но **падает**. Пункт считается покрытым (объект
  реализован), но в коде баг — его чинят через `/object`.
- **✗ не покрыт** — теста на этот пункт нет. Реализованность под вопросом.
- **⊘ вручную** — пункт по своей природе нельзя проверить тестом (чистая
  визуальная декорация: анимация, цвет, «приятно глазу»). Определяй это по смыслу
  и по `Verification` уровня, а не по пометкам — в самом объекте ничего помечать
  не нужно. Автотеста не требует, «дырой» не считается.

Объект считается **реализованным**, когда всё его поведение покрыто тестами
(падающие тесты = баги, а не «не реализовано» — см. `/object`).

## Формат отчёта

```
<object-name>  (<Имя объекта>)
  ✓ 1. <поведение>           <test-id>:<file>:<line>
  ⚠ 2. <поведение>           <test-id>:<file>:<line>   — падает
  ✗ 3. <поведение>           — нет теста
  → покрыто N/M, багов K
```

Если проверяешь все объекты — добавь сводку: сколько объектов полностью
реализовано, сколько с дырами, сколько с багами.

## Поток

1. Прогони `scripts/check-object-names.sh` — убедись, что имена объектов
   уникальны (от этого зависит однозначность ссылок `// object:`). Нашлись
   дубликаты — сообщи и остановись: отчёт по неоднозначным именам недостоверен.
2. Определи область: один объект (по имени) или все.
3. Собери поведение из объекта и тесты по ссылке `// object:`.
4. Сопоставь по смыслу, прогони тесты.
5. Покажи отчёт. Если есть дыры или баги — назови их прямо, но ничего не меняй;
   дальше пользователь сам решит, идти ли в `/object`.
