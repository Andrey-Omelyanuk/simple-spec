# /story

Режим **источника**: снять с пользователя историю (сырой голос — что он хочет и
зачем) и дистиллировать её в объекты `oos/`. История — **не спека**, а
датированная запись намерения (см. README). Спека и синхронизация с кодом живут
только на объектах.

## Что ты делаешь

1. Обсуждаешь с пользователем историю: что нужно, зачем, какие сценарии он видит.
   Языком пользователя, без код-жаргона.
2. Записываешь историю в `stories/` как запись лога — **append-only**, с датой в
   имени (`ГГГГ-ММ-ДД-<тема>.md`). Старые истории не переписываешь: они фиксируют
   намерение на момент времени.
3. **Дистиллируешь** историю в объекты `oos/`: раскладываешь её поведение по
   **активным** объектам (см. `src/OBJECT.md`, раздел «Чьё поведение»),
   создаёшь/обновляешь объекты. «Зачем» из истории кладёшь в объект строкой
   «Назначение» только если оно неочевидно.
4. Код — только по **явному** указанию пользователя (как в `/object`).

## Чего ты НЕ делаешь

- Не синхронизируешь истории с кодом и не измеряешь их — это мягкая односторонняя
  стрелка. Меряется только `object → code` (`/object-check`).
- Не переписываешь старые истории под новый код. Устаревшая история — не баг, это
  запись прошлого намерения.
- Не пишешь код автоматически. Не трогаешь скелет — это `/architect`.

## Дистилляция: как раскладывать по объектам

- Одна история обычно трогает несколько объектов — разнеси её поведение между
  ними, не дублируя.
- Взаимодействие принадлежит **активному** объекту; пассивный получает только
  свой инвариант. Пример: «подобрал сердечко → +10 здоровья, но не выше максимума»
  → Сердечко: «лечит подобравшего на 10»; Персонаж: «здоровье ≤ макс».
- Общее правило (тот же инвариант из нескольких историй) живёт у владельца один
  раз.

## Поток

1. Сними историю, запиши в `stories/` (append-only, с датой).
2. Разложи её поведение по объектам `oos/` (создай/обнови).
3. Дальше — `/object` для работы с объектами и кодом.
