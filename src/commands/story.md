# /story

Снимаешь **намерение** — что нужно и зачем, словами пользователя — и записываешь
его в `stories/`. История — это голос плюс твоя **дистилляция**: как ты понял
задачу. Она — единственный вход для реализации (`/start`). Результат команды —
один файл истории: ни кода, ни ветки, ни коммита, ни PR.

## Формат

Файл `stories/ГГГГ-ММ-ДД-<имя>.md` — один на одну историю. Внутри два слоя:
**голос** (сырьё) и **дистилляция** (понимание, по которому проверяется
реализация).

```
# {Имя}

{Голос: что нужно и зачем, как говорит пользователь. Один-два абзаца — сырьё,
не дистиллят.}

## Поведение
Пункты — это сценарии, будущие имена тестов.
- {что наблюдает пользователь, когда происходит то-то}
- ...
```

Заголовок `## Поведение` обязателен — по его пунктам `/start` реализует и
проверяет. Остальные разделы берёшь по надобности (Состояния, Связи, Вне рамок);
пустых не оставляй. Имя — kebab-case, оно же заголовок.

Пункт поведения — один проверяемый результат, наблюдаемый, с условием и
результатом. Пункт, к которому нельзя придумать проверку, — не пункт, а
пожелание.

Это только файл намерения. Устаревшая история — не баг, а запись прошлого
намерения; `stories/` — лог, старые записи не переписывают.

## Поток

1. **Сними голос** — что нужно и зачем, как говорит пользователь. Кода и
   код-жаргона здесь нет.
2. **Сверь** — по именам файлов и заголовкам в `stories/`, целиком читай только
   похожие; плюс код по теме. Лог растёт, читать его весь незачем. Нашёл повтор
   или конфликт — покажи и спроси, что делать.
3. **Спроси**, пока не всё ясно.
4. **Дистиллируй** голос в пункты поведения и **покажи историю** по формату.
5. Пользователь подтвердил, что понял верно, — запиши файл. На этом команда
   заканчивается.

## Чего ты НЕ делаешь

- Не пишешь код и тесты — это `/start`.
- Не реализуешь на месте, не создаёшь ветку и не коммитишь — история лишь
  фиксирует намерение файлом.
- Не переписываешь старые записи `stories/` — это лог намерений.
