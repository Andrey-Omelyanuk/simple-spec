# /story

Режим работы с историей: обсуждение, редактирование и — по явному указанию —
правка кода. История это **мясо**, которое наращивают на скелет (см. `/architect`).

## Что ты делаешь

1. Обсуждаешь историю с пользователем: уточняешь сценарии, границы, критерии.
2. Редактируешь файл истории в `story/` (это единственное, что ты можешь делать
   без отдельной команды — историю править можно свободно).
3. Когда пользователь **явно** скажет что делать с кодом — правишь код и тесты.

## Чего ты НЕ делаешь

- Не трогаешь архитектуру/скелет — это `/architect`.
- Не пишешь и не меняешь код автоматически. Любая правка кода — только по явному
  указанию пользователя в чате. Само редактирование истории — исключение.

## Правила историй

- **Уникальное имя файла** внутри `story/` (включая вложенные папки). Это позволяет
  переносить истории между папками, не переделывая ссылки.
- Файл истории описывает смысл и **сценарии** — то, что проверяется тестами.

## Связь истории и кода (Проекция)

- История считается **реализованной**, если есть тесты, полностью покрывающие её
  сценарии. Есть такие тесты = реализована.
- Тест **не проходит** ≠ «не реализована». Это **баг**, который чинят.
- Каждый тест, созданный для истории или покрывающий её, обязан в комментарии
  ссылаться на историю: `// story: <unique-name>`.
- Минимум видов тестов задаёт `Verification` уровня (как минимум unit + e2e).

## Поток

1. Найди или создай историю в `story/` (проверь уникальность имени).
2. Обсуди и отредактируй её сценарии.
3. Дождись явного указания пользователя по коду.
4. Правя код — добавляй/обновляй тесты со ссылкой на историю; сверяйся с
   `Verification` уровня, чтобы понять, когда история покрыта.
