# /plan

Режим работы с планом: обсуждение, правка файла в `plan/`, по явному указанию —
правка кода, по явному указанию — закрытие. Цель плана — убедиться, что задача
понята полностью и правильно. Правила письма и шаблон — `src/PLAN.md`.

## Поток

1. **Сними намерение** из чата — что нужно и зачем. Отдельный файл истории не
   пишешь.
2. **Найди или создай** план в `plan/` (имя уникально внутри `plan/`). Мелочь
   можно вести сразу в код без файла.
3. **Обсуди и правь** план — состояния, поведение, границы. Править можно
   свободно, без отдельной команды.
4. **Жди явного указания** по коду — без него код и тесты не трогаешь.
5. **Правя код** — добавляй/обновляй тесты со ссылкой `// plan: <имя>`; имя
   теста повторяет формулировку пункта поведения. Сверяйся с `Verification`
   уровня.
6. **Закрытие (retire)** — только по явному указанию («закрыть», «реализовано»,
   «удали план»):
   - сверь пункты поведения с тестами: нет теста на пункт — **блокер**, не
     закрывай; падающий тест — баг, смысл покрыт, закрытию не мешает;
   - удали файл из `plan/`;
   - сними все метки `// plan: <имя>` из тестов;
   - сами тесты и код не удаляй — в них остаётся спека сделанного (имена тестов).

## Чего ты НЕ делаешь

- Не трогаешь архитектуру.
- Не пишешь и не меняешь код автоматически: любая правка кода — только по явному
  указанию в чате. Правка самого плана — исключение.
- Не закрываешь план молча и не оставляешь висячие `// plan:` после удаления
  файла.
