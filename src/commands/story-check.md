# /story-check

Режим **проверки**: насколько история реализована в коде. Команда ничего не пишет
и не чинит — она только смотрит и докладывает. Это «измерительный прибор» для
Проекции (см. README): история ↔ тесты ↔ код.

## Что ты делаешь

1. Находишь историю в `story/` по имени (или берёшь все, если имя не указано).
2. Вынимаешь из файла истории её **сценарии** (блок `## Сценарии`) и смысл.
3. Находишь все тесты со ссылкой на эту историю: `// story: <unique-name>`.
4. **Смыслово сопоставляешь** содержимое найденных тестов со сценариями: читаешь,
   что именно тест проверяет, и решаешь, какой сценарий он покрывает. Ссылка —
   это только указатель на нужные тесты; покрытие определяется по сути теста, а не
   по наличию ссылки.
5. Прогоняешь эти тесты и смотришь результат.
6. Выдаёшь отчёт: что покрыто, что нет, что падает.

## Чего ты НЕ делаешь

- Не пишешь и не правишь тесты и код. Совсем. Это задача `/story`.
- Не редактируешь историю. Это задача `/story`.
- Не «чинишь» падающие тесты — только сообщаешь о них как о багах.

## Как читать результат

Для каждого сценария — один из статусов:

- **✓ покрыт** — есть тест, проверяющий этот сценарий, и он проходит.
- **⚠ баг** — тест на сценарий есть, но **падает**. Сценарий считается покрытым
  (история реализована), но в коде баг — его чинят через `/story`.
- **✗ не покрыт** — теста на этот сценарий нет. Реализованность под вопросом.
- **⊘ вручную** — сценарий по своей природе нельзя проверить тестом (чистая
  визуальная декорация: анимация, цвет, «приятно глазу»). Определяй это по смыслу
  сценария и по `Verification` уровня, а не по пометкам в истории — в самой истории
  ничего помечать не нужно. Автотеста не требует, «дырой» не считается.

История считается **реализованной**, когда все её сценарии покрыты тестами
(падающие тесты = баги, а не «не реализовано» — см. `/story`).

## Формат отчёта

```
<story-name>  (<Заголовок истории>)
  ✓ 1. <сценарий>            <test-id>:<file>:<line>
  ⚠ 2. <сценарий>            <test-id>:<file>:<line>   — падает
  ✗ 3. <сценарий>            — нет теста
  → покрыто N/M, багов K
```

Если проверяешь все истории — добавь сводку: сколько историй полностью
реализовано, сколько с дырами, сколько с багами.

## Поток

1. Прогони `scripts/check-story-names.sh` — убедись, что имена историй уникальны
   (от этого зависит однозначность ссылок `// story:`). Нашлись дубликаты —
   сообщи и остановись: отчёт по неоднозначным именам недостоверен.
2. Определи область: одна история (по имени) или все.
3. Собери сценарии из истории и тесты по ссылке `// story:`.
4. Сопоставь по смыслу, прогони тесты.
5. Покажи отчёт. Если есть дыры или баги — назови их прямо, но ничего не меняй;
   дальше пользователь сам решит, идти ли в `/story`.
