# /object

Режим работы с объектом: обсуждение, редактирование и — по явному указанию —
правка кода. Объект — единица спеки, с которой работает конечный пользователь;
его наращивают на скелет (см. `/architect`).

## Что ты делаешь

1. Обсуждаешь объект с пользователем: уточняешь состояния, поведение, границы.
2. Редактируешь файл объекта в `oos/` (это единственное, что можно делать без
   отдельной команды — объект править можно свободно). Шаблон — `src/OBJECT.md`.
3. Когда пользователь **явно** скажет что делать с кодом — правишь код и тесты.

## Чего ты НЕ делаешь

- Не трогаешь архитектуру/скелет — это `/architect`.
- Не пишешь и не меняешь код автоматически. Любая правка кода — только по явному
  указанию пользователя в чате. Само редактирование объекта — исключение.

## Правила объектов

- **Язык пользователя, не программиста.** Описывай только наблюдаемое поведение и
  смысл; никакого код-жаргона (сигнатуры функций, `dt`, формулы, форматы данных,
  «нормализация», «тик»).
- **Чьё поведение.** Взаимодействие принадлежит **активному** объекту (Портал
  перемещает, Сердечко лечит); пассивный держит только свои инварианты. Общее
  правило живёт у владельца один раз — не дублируем по объектам.
- **«Назначение»** добавляй только когда смысл объекта неочевиден.
- **Уникальное имя файла** внутри `oos/` (включая вложенные папки). Это позволяет
  переносить объекты между папками, не переделывая ссылки.

## Связь объекта и кода (Проекция)

- Объект считается **реализованным**, если есть тесты, полностью покрывающие его
  поведение. Есть такие тесты = реализован.
- Тест **не проходит** ≠ «не реализован». Это **баг**, который чинят.
- Каждый тест, созданный для объекта или покрывающий его, обязан в комментарии
  ссылаться на него: `// object: <unique-name>`.
- Минимум видов тестов задаёт `Verification` уровня (как минимум unit + e2e).

## Поток

1. Найди или создай объект в `oos/` (проверь уникальность имени).
2. Обсуди и отредактируй его состояния и поведение.
3. Дождись явного указания пользователя по коду.
4. Правя код — добавляй/обновляй тесты со ссылкой на объект; сверяйся с
   `Verification` уровня, чтобы понять, когда объект покрыт.
