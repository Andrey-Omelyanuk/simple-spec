# Web App

Монорепо: backend-монолит на Django, SPA-клиент, инфраструктура. Каждый сервис и
каждое Django-приложение — отдельный уровень со своим `AGENTS.md`. Формат уровня
— `src/LEVEL.md`.

## Схема уровней

```
root                        ← root.md
├── {backend}/              ← django-service.md  (монолит: API, домен)
│   └── apps/<домен>/       ← django-app.md      (одно приложение Django)
├── {web}/                  ← сервис по надобности (SPA, иной стек)
├── {infra}/                ← сервис по надобности (Docker Compose, gateway, БД)
└── <ещё сервис>/           ← сервис по надобности
```

Backend и его `apps/*` обязательны. Остальные сервисы заводятся по надобности —
уровень появляется, когда у него есть своя граница и свой `Verification`. Ещё
один сервис на Django выстраивают по тому же `django-service.md`.

## Как раскрывать

1. `/architect` читает `src/templates/web-app/` и `src/LEVEL.md`.
2. По `root.md` — корневой `AGENTS.md`: имя проекта, границы монорепо, схема
   папок, как запускается и проверяется целое.
3. По `django-service.md` — `AGENTS.md` backend-сервиса: стек, список `apps/*`,
   общие паттерны, способ проверки.
4. По `django-app.md` — по одному `apps/<домен>/AGENTS.md` на каждое приложение:
   границы app'а, модели, REST, паттерны, проверка.
5. Имена папок и доменное наполнение (`{...}`) — из разговора с пользователем,
   не выдумывать.
