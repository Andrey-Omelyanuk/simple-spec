# OBJECT.md

Файл в `oos/` описывает один **объект**, с которым работает конечный
пользователь. Это единица спеки — маленький смысл, который проецируется в код.

Язык — пользователя, не программиста: только наблюдаемое поведение и смысл,
никакого код-жаргона (сигнатуры, `dt`, формулы, форматы данных, «нормализация»,
«тик»). Как это считать — забота кода и тестов уровня.

Объект может крениться в две стороны (формат один, разделы берёшь по надобности):
- **сущность** — главное это набор поведений (Сердечко, Портал);
- **процесс** — главное это переходы между состояниями (Заявка, Заказ). Поток во
  времени — это объект-владелец потока со state-машиной, а не отдельная форма.

## Чьё поведение

Взаимодействие двух объектов принадлежит **активному** (инициирующему): Портал
перемещает, Сердечко лечит. Пассивный объект держит только свои инварианты
(Персонаж: «здоровье ≤ макс»). Если правило симметрично и ничьё — заводи
отдельный объект-правило.

## Связь с кодом

Каждый тест, покрывающий поведение объекта, ссылается на него в комментарии:
`// object: <unique-name>`, где имя — имя файла без `.md`. Имя уникально внутри
`oos/` (включая вложенные папки) — так ссылки не ломаются при реорганизации папок.
