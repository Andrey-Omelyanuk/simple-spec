## Ошибки концепта

- [ ] **Жизненный цикл объекта**: протокол переименования и удаления — миграция
  ссылок `// object:` в тестах, судьба тестов при удалении объекта.
- [ ] **Обратный дрейф в `/object-check`**: нет статуса для тестов-сирот — тест
  ссылается на объект, но не соответствует ни одному пункту поведения (код
  обогнал спеку или тест устарел). Прибор меряет проекцию только в одну сторону.
- [ ] **Синтаксис ссылки привязан к C-подобным языкам**: определить формат как
  «комментарий, содержащий `object: <имя>`», конкретный синтаксис — забота
  `Verification` уровня. Заодно решить: может ли один тест ссылаться на два
  объекта (тест взаимодействия).
- [ ] **Языковая политика не зафиксирована**: объявить заголовки шаблона
  (`## Поведение`, `## Состояния`, …) каноническими маркерами — от них зависит
  парсинг в `/object-check`; задать конвенцию имени файла объекта (язык,
  kebab-case).
- [ ] **Скрипты непортабельны (GNU-измы)**: `find -printf` в
  `check-object-names.sh` и `\b` в sed `install.sh` — на macOS ломаются молча
  (ссылки на README не перепишутся, проверка имён упадёт).
- [ ] **Непоследовательная модель согласия**: `/story` пишет объекты сразу, без
  чекпоинта, `/architect` требует явного одобрения. Либо показывать дистилляцию
  перед записью, либо задокументировать, почему объекты дёшевы и это ок.
