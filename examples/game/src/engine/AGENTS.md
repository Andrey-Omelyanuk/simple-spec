# Engine (IO-оболочка)

## Overview
Тонкий слой ввода-вывода: игровой цикл, отрисовка состояния `sim` на canvas,
чтение клавиатуры, звук.

## Boundaries
Делает: запускает цикл (`requestAnimationFrame`), читает ввод, вызывает
`sim.update`, рисует полученное состояние.
Не делает: не содержит игровых правил — только показывает то, что вернул `sim`.

## Tech Stack
TypeScript, Canvas 2D API, браузерные API (`requestAnimationFrame`, `KeyboardEvent`).

## Architecture
```
engine/
  loop.ts      цикл: каждый кадр input → sim.update → render
  renderer.ts  отрисовка состояния мира на canvas
  input.ts     сбор нажатых клавиш в объект input для sim
```
Файлы заводим по мере необходимости.

## Patterns
- Один кадр: собрать `input` → `sim.update(state, input, dt)` → `renderer.draw(state)`.
- Уровень не хранит игрового состояния — оно приходит из `sim` и туда же возвращается.

## Non-Obvious Rules
- Никакой игровой логики здесь: если в истории появляется правило поведения мира —
  оно идёт в `sim`, а не сюда. Зависимость строго `engine` → `sim`.

## Verification
Автотестов нет — слой состоит из сайд-эффектов (рендер, ввод, rAF), которые юнитом
не проверить осмысленно. Проверка ручная: запуск через `vite` и визуальный осмотр.
Поэтому история не должна требовать собственных тестов на этом уровне — её
проверяемая суть выносится в `sim`.

## Dependencies
- `sim/` (читает состояние, вызывает `update`).
