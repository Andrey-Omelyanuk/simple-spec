# Simple Spec — простой способ разработки через ИИ-агентов
Система превращает хаотичную разработку в управляемый конвейер: `Spec` (что нужно) → `Todo` (как реализуем) → `Code` (результат).

## Определения
- **Spec** — центральная сущность, описывающая требования, границы и цели артефакта.
- **Todo** — задача на исполнение агентом 
- **UserStory** (опционально) — истории от лица пользователя, описывающие сценарии использования. Хранятся в папке `user-story/` (один файл = один домен).

## Инвентарь
Внутри одной еденицы разработки всегда есть файлы:
- `spec.md` - кроме требований так же содержит краткое описание единицы разработки и ее контекст 
- `todo.md` - локальный список задач по реализации текущего `spec.md`. Каждая задача атомарна.
- `agent.md` - описывает агента, его роль, скилы, используемые инструменты, запреты, как он работает, предпочтения и тд.

## Режимы работы
- **`/think`** — обсуждение требований и архитектуры. Формирует/уточняет только `spec.md` и `todo.md`.
- **`/user-story`** — генерация пользовательских сценариев в `user-story/`. Финальным шагом предлагает перейти в `/think` для конвертации новых историй в `spec.md` + `todo.md`.
- **`/do-it`** — выполнение задач из `todo.md`. Каждая задача начинается с чистого контекста (читает только первую задачу в `todo.md`, релевантные файлы и `agent.md`). Задача удаляется из `todo.md` только после успешного ее выполнения.
- **`/audit`** — вспомогательный режим для сверки кодовой базы с `spec.md`. Находит расхождения и только добавляет в `todo.md` задачи на устранение.
- **`/import`** — вспомогательный режим для миграции существующего кода в Simple Spec. Анализирует существующие файлы и генерирует только черновик `spec.md` + `todo.md`.

## Общие правила работы агента (даже если они не описаны в agent.md)
- Агент переключается между режимами явно. Параллелизм запрещён.
- Агент всегда исполняеться только внутри контекста описанного в `spec.md`.
