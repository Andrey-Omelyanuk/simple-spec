# Simple Spec

Намерение приходит из чата и оседает в **плане** (`plan/`),
затем реализуется в **коде**. Код — источник истины.

[intent] ⇢ [plan] → [code]

- **Intent** — голос пользователя в чате: что нужно и зачем. Не хранится отдельным файлом.
- **Plan** — план в `plan/`: сущность предметной области языком пользователя 
  (Персонаж, Портал, Заявка). Составляют, чтобы убедиться: задача понята полностьюи правильно. 
  Пустой `plan/` значит: незакрытого нет.
- **Code** — реализация и источник истины. Спека сделанного живёт в тестах: 
  имена на языке пользователя повторяют пункты поведения.

Стрелка `plan → code` — проекция, пока план жив. После покрытия поведения
тестами план **закрывают**: файл из `plan/` удаляют, временные метки `// plan:`
снимают из тестов. Тесты и код остаются.


## План

Цель плана — убедиться, что задача понята полностью и правильно. Пока это не
так, план живёт файлом в `plan/`. Описывает себя языком пользователя, не
программиста: что это, какие состояния, как себя ведёт, с кем связан. Бывает
**сущностью** (суть в поведениях: Сердечко, Портал) или **процессом** (суть в
переходах состояний: Заявка, Заказ). Взаимодействие принадлежит **активной**
сущности. Правила и шаблон — `src/PLAN.md`.

Мелочь можно вести сразу в код без файла в `plan/`.

## Команды

`/architect` — обсуждение архитектуры; тут создаётся **скелет** приложения:
    файловая иерархия с `AGENTS.md` на каждом уровне (модуль, сервис, библиотека).

`/plan` — обсуждение плана, его правка, по явному указанию — правка кода, и
    по явному указанию — **закрытие** (retire): удалить файл из `plan/`, снять
    метки `// plan:` из тестов. Перед закрытием сверь пункты поведения с тестами:
    нет теста на пункт — ещё рано закрывать; падающий тест — баг, его чинят
    отдельно, закрытию смысла не мешает.

## Правила

Основная цель плана — убедиться, что задача понята полностью и правильно; затем
реализовать её в коде. После реализации истина — код и тесты; план не держат
как вечную спеку рядом.

Пока файл в `plan/`, тесты ссылаются на него (`// plan: <имя>`). После закрытия
метки снимают — соответствие «пункт ↔ тест» остаётся в именах тестов. Какими
видами тестов пользоваться — решает `Verification` уровня. Подробности —
`src/PLAN.md`.

Важные решения из диалога, которые нельзя вывести из кода, сохраняют в коде
или в `Non-Obvious Rules` уровня (`AGENTS.md`).

## Установка

Команды и подложку ставит `install.sh` — в проект или глобально для пользователя:

```
./install.sh <путь-к-проекту> [служебная-папка]   # в конкретный проект
./install.sh --global [opencode|claude|cursor]    # глобально для юзера
```

**В проект:** служебная папка по умолчанию `.opencode` (для Claude Code —
`.claude`, для Cursor — `.cursor`). Скрипт подстраивает подпапку команд под
инструмент, кладёт рядом подложку (`PLAN.md`, `AGENTS.md`, скрипт проверки) и
создаёт `plan/`, если его нет.

**Глобально:** команды едут в командную папку инструмента (opencode →
`~/.config/opencode`, claude → `~/.claude`, cursor → `~/.cursor`), подложка — в
`simple-spec/` рядом, ссылки в командах переписываются на абсолютный путь к ней.
`plan/` не создаётся — он пер-проектный, его заводят сами команды в текущем
проекте.

Повторный запуск обновляет кит; планы в `plan/` не трогает.
