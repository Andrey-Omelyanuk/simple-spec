# Simple Spec

Набор команд для ИИ-агента (opencode, Claude Code, Cursor). Требования
обсуждают в чате, понимание задачи фиксируют **планом**, план реализуют
**кодом** — и удаляют. Постоянной папки со спеками нет: спека сделанного живёт
в именах тестов.

## Модель

[intent] ⇢ [plan] → [code]

- **Intent** — голос пользователя в чате: что нужно и зачем. Отдельным файлом
  не хранится.
- **Plan** — `PLAN.md` в корне проекта: сущность предметной области языком
  пользователя (Персонаж, Портал, Заявка). Нужен, чтобы убедиться — задача
  понята полностью и правильно. Живёт в собственной ветке; в главной ветке
  этого файла нет.
- **Code** — реализация и источник истины. Имена тестов на языке пользователя
  повторяют пункты поведения плана — это и есть спека сделанного.

Стрелки разные не для красоты: `⇢` — намерение нигде не сохраняется, осело в
плане и всё; `→` — проекция: пункты поведения становятся именами тестов. Она
переживает план — файл удаляют, имена остаются.

Вторая опора модели — **уровень**: `AGENTS.md` в каждой значимой папке
иерархии. План говорит, *что* должен увидеть пользователь; уровень говорит,
*как это проверяется* (раздел `Verification`) и какие правила нельзя вывести из
кода (`Non-Obvious Rules`). Без уровня нельзя понять, реализован ли план.

## Цикл ветки

```
main ──●──────────────────────────────────●── merge: только код и тесты
        \                                 /
         ●── план ──●──●── код + тесты ──●
       /plan      /start              /finish → PR: текст плана в теле
```

`/plan` — обсуждение требований до полного понимания. Результат — `PLAN.md`
первым коммитом новой ветки (имя ветки = имя плана). Кода здесь нет.

`/start` — реализация плана ветки: код и тесты (имя теста повторяет пункт
поведения), «почему»-комментарии, доказательство прогоном тестов.

`/finish` — закрытие: на каждый пункт поведения — тест, бывший зелёным; затем
удаление плана и PR в главную ветку с текстом плана в теле.

`/start` и `/finish` запускают свежей сессией: контекста ветки достаточно, а
проверяет не тот, кто строил. Net-диф ветки — только код и тесты; намерение
остаётся в описании PR, главная ветка чиста.

Мелочь можно вести без `PLAN.md`: ветка, `/start` сразу, `/finish` без
retire-проверок.

`/architect` — вне цикла: скелет приложения, то есть файловая иерархия с
`AGENTS.md` на каждом уровне. Растёт по надобности, не наперёд.

## Почему так

Спеку, которую держат рядом с кодом вечно, рано или поздно перестают
обновлять — и тогда врут оба, а верить приходится коду. Simple Spec не даёт
такой спеке появиться: план существует ровно до момента, когда поведение
покрыто тестами, и удаляется в том же дифе. Дальше проверяемым остаётся то, что
исполняется, — тесты; понимание задачи остаётся в описании PR; решения, которые
нельзя вывести из кода, — в «почему»-комментариях (самое ценное — отвергнутая
альтернатива) и в `Non-Obvious Rules` уровня. Закрытие плана именно это и
проверяет: после удаления файла и конца сессии таким решениям больше негде
жить.

Папки для планов нет по той же причине: план один на ветку и живёт до
`/finish` — хранить и раскладывать по вложенным папкам нечего, а папка со
временем и стала бы той вечной спекой. Фиксированный путь ещё и упрощает
проверку: net-диф ветки просто не содержит `PLAN.md`.

Чем это не является: не трекер задач, не документация архитектуры (её место —
`AGENTS.md` уровня), не BDD-фреймворк — какими видами тестов проверять, решает
уровень.

## Что где лежит

- `src/PLAN-FORMAT.md` — формат плана: шаблон, чьё поведение, имена тестов.
- `src/AGENTS.md` — формат уровня: границы, паттерны, `Verification`.
- `src/commands/` — сами команды.

## Установка

Команды и кит (`PLAN-FORMAT.md`, `AGENTS.md`) ставит `install.sh` — в проект
или глобально для пользователя:

```
./install.sh <путь-к-проекту> [служебная-папка]   # по умолчанию .opencode
./install.sh --global [opencode|claude|cursor]    # глобально для юзера
```

Кит едет рядом с командами, ссылки внутри команд переписываются на его путь.
Повторный запуск обновляет кит и не трогает `PLAN.md` проекта. Подробности —
в шапке `install.sh`.
