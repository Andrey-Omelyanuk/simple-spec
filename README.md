# Simple Spec — простой способ разработки через ИИ-агентов

## 1. Фундаментальная идея
- Система превращает хаотичную разработку в управляемый конвейер: `Spec` (что нужно) → `Todo` (как реализуем) → `Code` (результат).
- Файлы как контракт: единственный источник истины — текстовые файлы (`spec.md`, `todo.md`). Никакого скрытого состояния.
- Локальность: агент работает строго в контексте директории, описанной текущим `spec.md`.
- Удаление задач: выполненная задача физически удаляется из `todo.md`. История фиксируется в Git.
- Правило 1:1: `spec.md` и `todo.md` всегда лежат рядом. Дочерние спеки наследуют ограничения родителей, но не дублируют их.

## Определения
- **Spec** — центральная сущность, описывающая требования, границы и цели артефакта.
- **Todo** — локальный список задач по реализации текущего `spec.md`. Каждая задача атомарна и проверяема.
- **UserStory** (опционально) — истории от лица пользователя, описывающие сценарии использования. Хранятся в папке `user-story/` (один файл = один домен). Используются как вход для `/think`.

## Определения 
**Spec** это центральная сущьность которая описывает чего мы хотим.
**ToDo** это список из того как мы будем реализовывать **spec**.
**UserStory** это истории от лица пользователя, того что он может или не может делать. Опционально.

## Режимы работы
Агент переключается между режимами явно. Параллелизм запрещён.

- **`/think`** — обсуждение требований и архитектуры. Формирует/уточняет только `spec.md` и `todo.md`. Требует подтверждения человека перед фиксацией.
- **`/user-story`** — генерация пользовательских сценариев в `user-story/`. Финальным шагом предлагает перейти в `/think` для конвертации историй в `spec.md` + `todo.md`.
- **`/do-it`** — выполнение задач из `todo.md`. Каждая задача начинается с чистого контекста (читает только текущий `todo.md`, релевантные файлы и `agent.md`). Задача удаляется из `todo.md` только после успешной локальной валидации (тесты/линтер/сборка).
- **`/import`** — вспомогательный режим для миграции существующего кода в Simple Spec. Анализирует структуру и генерирует черновик `spec.md` + `todo.md`. Не изменяет код.
- **`/audit`** — вспомогательный режим для сверки кодовой базы с `spec.md`. Находит расхождения и добавляет в `todo.md` задачи на устранение. Read-only для кода.

## Режимы 
**/think** режим которвый помогает обсудить с ИИ чего мы хотим и формирует результат только в `spec.md` и `todo.md`.
**/user-story** режим который помогает обсудить с ИИ что может делать пользователь и формирует результат только в папке `user-story`, 
где каждый файл это один домен с набором историй. Финальным шагом являеться переход в **/think** режим для формирования `spec.md` и `todo.md`.
**/do-it** режим который запускает агента который начинает выполнять задачи в `todo.md`. Каждая задача начинаеться с чистого контекста.
**/import** вспомогательный режим для миграции в **Simple Spec**, он формирует `spec.md` из существующей кодовой базы. 
**/audit** вспомогательный режим который помогает найти расхождения между `spec.md` и кодовой базой, итогом должны быть задачи в `todo.md` которые описывают как устранить эти расхождения.

## Правила исполнения
1. **Изоляция контекста**: агент не сканирует проект целиком. Читает только файлы, явно разрешённые текущим `spec.md` или `agent.md`.

## `agent.md` — конфигурация возможностей
Файл всегда лежит рядом с `spec.md`. Описывает не абстрактные «скиллы», а конкретные параметры исполнения:
- Стек и версии
- Разрешённые команды и инструменты (линтер, тест-раннер, сборщик)
- Ограничения (запреты на глобальный поиск, сторонние API, изменение конфигов)
- Стандарты кода и форматирования
- Стратегия валидации для `/do-it`
