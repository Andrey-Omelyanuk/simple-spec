# Simple Spec

Набор команд для ИИ-агента (opencode, Claude Code, Cursor). Требования фиксируют
понимание задачи, план реализуют **кодом**, а спека сделанного живёт в именах
тестов. Работать можно двумя потоками — **историей** или **планом**; команды
обоих живут рядом.

## Модель

[story] → [code]   ·   [intent] ⇢ [plan] → [code]

- **Story** — файл в `stories/`: голос пользователя (что нужно и зачем) и план —
  дистиллят голоса: состояния, поведение, границы. Это **append-only лог
  намерений**, как changelog: старые записи не переписывают под новый код.
- **Plan** — `PLAN.md` в корне: сущность предметной области языком пользователя.
  Живёт в собственной ветке; в главной ветке этого файла нет.
- **Code** — реализация и источник истины. Имена тестов на языке пользователя
  повторяют пункты поведения — это и есть спека сделанного.

Стрелка `→` — проекция: пункты поведения (истории или плана) становятся именами
тестов. Она переживает устаревание записи: лог остаётся записью прошлого
намерения, имена тестов продолжают говорить, что сделано.

Вторая опора модели — **уровень**: `AGENTS.md` в каждой значимой папке
иерархии. Запись говорит, *что* должен увидеть пользователь; уровень говорит,
*как это проверяется* (раздел `Verification`) и какие правила нельзя вывести из
кода (`Non-Obvious Rules`). Без уровня нельзя понять, реализована ли фича.

## Цикл ветки — историей

```
main ──●──────────────────────────────────●── merge: код, тесты и история
        \                                  /
         ●── история ──●── код + тесты ────
       /story       (реализация отдельной сессией)
```

`/story` — снять голос пользователя, записать в `stories/` голос и план.
Результат — запись первым коммитом новой ветки (имя ветки = имя истории).
Дальше реализация отдельной сессией: свежий агент читает историю как единственный
источник понимания и пишет код и тесты, затем PR.

## Цикл ветки — планом

```
main ──●──────────────────────────────────●── merge: только код и тесты
        \                                  /
         ●── план ──●──●── код + тесты ──●
       /plan      /start              /finish → PR: текст плана в теле
```

`/plan` — обсуждение требований до полного понимания. Результат — `PLAN.md`
первым коммитом новой ветки (имя ветки = имя плана). `/start` — реализация
плана ветки: код и тесты. `/finish` — закрытие: проверка, что каждый пункт
поведения покрыт зелёным тестом, затем удаление плана и PR.

Мелочь можно вести без файла: ветка, `/start` сразу, `/finish` без retire-проверок.

`/architect` — вне цикла: скелет приложения, то есть файловая иерархия с
`AGENTS.md` на каждом уровне. Растёт по надобности, не наперёд.

## Почему так

Постоянная спека, которую держат рядом с кодом вечно, рано или поздно перестают
обновлять — и тогда врут оба, а верить приходится коду. Simple Spec не даёт
такой спеке появиться — и не выбрасывает намерение. Проверяемым остаётся то, что
исполняется, — тесты; понимание задачи — в истории (`stories/`) или в тексте
плана и описании PR; решения, которые нельзя вывести из кода, — в
«почему»-комментариях (самое ценное — отвергнутая альтернатива) и в
`Non-Obvious Rules` уровня; отмена прежнего поведения — в сообщении коммита,
удалившего тест.

Чем это не является: не трекер задач, не документация архитектуры (её место —
`AGENTS.md` уровня), не BDD-фреймворк — какими видами тестов проверять, решает
уровень.

## Что где лежит

- `src/STORY-FORMAT.md` — формат истории: шаблон и пример, голос и план,
  формулировка пункта, чьё поведение, имена тестов.
- `src/PLAN-FORMAT.md` — формат плана: шаблон и пример, пункт поведения, чьё
  поведение, имена тестов, отмена прошлого.
- `src/AGENTS.md` — формат уровня: границы, паттерны, `Verification`.
- `src/commands/` — сами команды.

## Установка

Команды и кит (`STORY-FORMAT.md`, `PLAN-FORMAT.md`, `AGENTS.md`) ставит
`install.sh` — в проект или глобально для пользователя:

```
./install.sh <путь-к-проекту> [служебная-папка]   # по умолчанию .opencode
./install.sh --global [opencode|claude|cursor]    # глобально для юзера
```

Кит едет рядом с командами, ссылки внутри команд переписываются на его путь.
Повторный запуск обновляет кит и не трогает `stories/` и `PLAN.md` проекта.
Подробности — в шапке `install.sh`.
