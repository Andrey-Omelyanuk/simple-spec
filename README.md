# Simple Story
Разработка идущая от пользовательских историй. 

[story] -> [code]

Никакого `spec` - это лишнее.
Есть только Story и Code. Это два разных состояния которые синхронизируються.
В основном из Story в Code.

Нужно нарисовать одно состояние в виде пересекающихся окружностей, каждая это история.
И одну большую окружность - это код. Окружность это смысловое покрытие.
Каждая история это маленький смысл. Код же покрывает польностью (в идеале).
Стрелка между Story и Code с надписью "Проекция".

![Проекция Story в Code](docs/projection.svg)

Только 2 комманды:

/architect - режим обсуждение архитектуры, именно тут создаеться каркас приложения,
    в виде файловой иерархии со своими AGENTS.md на своих уровнях (модуль, сервис, библиотека и т.д.)
    Можно сказать что это скелет приложения.

/story - обсуждение истории, редактирование ее, и в конечном счете правка кода.
    Что бы понять реализованна ли история нужно просто найти тесты покрывающее полностью историю, 
    если есть тесты = история реализованна.
    А то что тесты не проходят это уже "баг" который нужно чинить.
    Можно сказать что story это мясо, которое наращивают на скелете.
    Что по итогу делать, пользователь явно должен указать в чате. Тут нет автоматического выволнения
    , кроме как редактирование истории.

Тут нет обязательства работать через историю, можно писать код как хочешь.
Основная цель это через конечного пользователя собирать истории и потом их реализовывать.

Проект обязан как можно больше тестов, они помогут лучше переносить истории в код.
Должны быть как минимум юнит тесты и e2e.
Если тест был создан для истории, или покрывает какую-то историю, в комментариях к ней
обязана быть ссылка на историю.

Имя файла истории должно быть уникально внутри папки story (включае всех ее дочерних).
Это позволит не переделывать ссылки на истории, даже если мы будем реарганизовывать 
истории в разные папки по смыслу.
