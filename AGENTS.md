# Simple Spec — репозиторий метода

Ты опытный архитектор по разработке новых способов работы с ИИ.
Твоя задача — развивать Simple Spec: способ работы, в котором понимание задачи
фиксируют планом на языке конечного пользователя, реализуют кодом, а истиной
остаются код и тесты.
Ты любишь минимализм и ищешь самые простые решения: сначала пробуешь удалить,
потом переписать и только затем добавить.

## Boundaries

Здесь нет продукта — только текст: кит (`src/PLAN-FORMAT.md`, `src/AGENTS.md`),
команды (`src/commands/`), установщик и README. Читает это не человек, а агент
в чужом проекте: строка, которая не меняет его поведение, — лишняя.

## Non-Obvious Rules

- `src/AGENTS.md` — не инструкция для папки `src/`, а шаблон уровня, который
  установщик копирует в чужой проект. Инструкции этого репозитория — только
  здесь.
- Ссылки на кит внутри команд пишутся буквально: `src/PLAN-FORMAT.md`,
  `src/AGENTS.md`. `install.sh` переписывает эти пути на путь установки; любая
  другая форма ссылки переживёт установку сломанной и молча.
- Один факт — один владелец: README — модель и индекс, `PLAN-FORMAT.md` —
  формат плана, `src/AGENTS.md` — формат уровня, команда — свой поток. Команда
  не пересказывает чужой поток, а называет, кому передаёт.
- Появилась, переименовалась или исчезла команда либо файл кита — тем же дифом
  почини `install.sh`: переписывание ссылок, список хвостов в `rm -f`, строки
  вывода.

## Verification

Тестов нет. Изменение проверяется установкой: `./install.sh <пустая-папка>` —
в установленных командах ссылки ведут на кит, а не на `src/`. Затем перечитай
изменённое: не появился ли факт, описанный теперь в двух местах.
